# Game Ready 开发设计草案

日期：2026-11-03。状态：用户已批准，已按此设计实施首版；实测范围见 `docs/game-ready-validation.md`。

## 目标与已确认需求

面向 16 GB 内存的 Windows 游戏电脑，在 LiteMonitor 中提供一键游戏准备功能，退出不需要的应用，为游戏腾出内存。

用户已确认：

- 白名单表示保留名单，名单之外的普通用户应用均属于关闭候选。
- 包含当前有窗口的应用，而非仅处理隐藏后台。
- 先请求正常退出，超时后强制结束；强制结束可能丢失未保存内容。
- 只清理一次，不在游戏期间持续拦截或反复结束进程。
- 由 Game Ready 启动选定的游戏。
- 记录本次关闭的应用，提供一键重新打开。
- 希望支持游戏启动后退出 Steam；能否启用由游戏兼容性决定。
- 首个关注的游戏为《影之刃零》。尚未实测该游戏在退出 Steam 后的行为。

## 方案选择

推荐直接二开 LiteMonitor，在原有菜单和设置中增加功能。项目基于 .NET 8 Windows Forms，已有菜单、主题与设置机制可以复用。

备选一：独立辅助工具，LiteMonitor 只负责启动。与上游隔离较好，但需要单独维护配置、界面和分发。

备选二：扩展插件框架。当前 JSON 插件主要用于周期获取和展示数据，原生处理仅有固定入口；需要新增手动操作、进程控制和配置界面，首版改动范围比直接二开更大。

首版建议采用直接二开，不为此新增通用插件平台。

## 用户流程

首次配置游戏和保留名单，随后从 LiteMonitor 菜单进入 Game Ready，选择游戏并点击开始。

1. 校验游戏启动配置、目标识别规则和保留名单；已有未恢复的会话时提示先恢复或明确放弃，不能覆盖记录。
2. 获取一次进程快照，计算候选关闭应用，保存会话记录及清理前可用物理内存。
3. 临时保护所选游戏的启动器、已运行的目标游戏及必要依赖，对其余候选执行退出。
4. 对有主窗口的候选发送正常关闭请求，并行等待，默认等待上限 10 秒，可配置。没有可用正常退出接口的后台应用等待同一宽限期后进入强制阶段。
5. 对超时未退的候选重新验证身份与保护规则，再强制结束。权限不足或身份无法核实则跳过并记录。
6. 若目标游戏未运行，使用配置的启动方式启动；已运行则复用，避免重复启动。
7. 等待匹配的游戏进程出现。默认启动超时 120 秒，可配置；进程出现不等于已进入主菜单。
8. 按游戏配置处理 Steam，显示关闭、跳过、失败结果及清理后的可用内存。内存差值只代表观测变化，不宣称全部由清理产生。
9. 游戏退出后提示可以恢复；用户点击“恢复应用”后重新打开本次实际关闭且支持恢复的应用。

取消只停止后续操作，不自动回滚已退出的应用；保留恢复入口。启动失败同样保留结果与恢复入口。

## 进程范围与保护规则

“其他全杀”的产品含义为关闭白名单外的普通用户应用，不等于结束所有系统进程。

- 默认只考虑当前 Windows 登录会话中的普通用户应用，不操作其他用户会话和系统服务。
- 始终保护 Windows 关键组件、桌面 Shell、驱动及相关服务、LiteMonitor 自身、当前所选游戏与必要依赖。
- 无法确认是否为普通应用、无法读取必要身份信息的进程采取跳过，并在结果中给出原因。
- 白名单优先使用可执行文件完整路径匹配，不只凭显示名称匹配；关联辅助进程以明确规则管理。
- 不能因为进程位于 Windows 目录就一概保护，也不能因为进程不在该目录就认定可结束。
- 执行前再次核对 PID、启动时间和路径，防止 PID 被复用后结束错误进程。
- 不对启动器执行不加区分的递归进程树终止；启动器的后代可能就是需要保留的游戏。
- 默认保护规则需要在实现阶段列出具体匹配项，并通过 Windows 实机验证，未知应用不靠猜测关联。
- NVIDIA Overlay 作为可选保留预设提供；是否启用由用户配置。需要 Alt+F1 时必须保留覆盖层所需组件。

清理对象固定为本次快照中的进程；游戏期间新启动或自行重启的应用不会再次被清理。

## Steam 策略

按游戏保存两种策略：保留 Steam 后台，或游戏启动后尝试退出 Steam。

默认保留 Steam 后台并关闭其主窗口；用户可为经实测兼容的游戏启用退出策略。启用后在目标进程出现、完成配置的延迟后请求 Steam 正常退出；拒绝退出或超时则保留并报告，不自动升级为强杀 Steam。Steam 是一般超时强杀策略的明确例外，避免其退出流程影响游戏。

延迟默认 30 秒，可配置；延迟不能证明游戏已不依赖 Steam。首版不自动推断兼容性，不通过修改游戏文件、绕过 DRM 或修改 Steam 配置来实现。

《影之刃零》标记为未经验证，默认保留 Steam 后台。官方商店列出 Denuvo、成就和云存档，但未确认游戏启动后可退出 Steam；这些标签也不能单独证明客户端必须一直运行。

若退出策略实际关闭了 Steam，将其记入恢复列表。重新启动客户端只为提供后续同步条件，不保证云存档一定同步成功。

## 应用恢复

恢复表示重新启动应用，不承诺恢复原窗口、文档、浏览器标签页和登录状态。

- 在退出之前将应用身份、已验证的启动入口及初始运行状态落盘；在退出之后更新实际结果。
- 按应用记录和去重，不按每个辅助进程逐一重启。只恢复本次实际关闭的应用。
- 优先使用用户配置或已验证的应用启动入口；不盲目重放任意进程命令行，不重启浏览器 renderer、更新器等内部辅助进程。
- 无法可靠确定启动入口的应用明确标记“需手动打开”，不假装已经恢复。
- 已经运行的应用跳过，失败可重试，重复点击不会重复拉起。
- LiteMonitor 重启后可读取未恢复会话，继续提供恢复入口。
- 恢复记录仅保存本机所需字段，不采集完整进程命令行中的令牌等敏感参数。

## 界面和配置

菜单入口：Game Ready、恢复应用。设置页包含游戏列表、保留名单、正常退出等待时间、游戏启动超时以及各游戏的 Steam 策略。

游戏配置支持 Steam App ID 或本地可执行文件、工作目录、显式启动参数，以及实际游戏进程路径。启动入口与实际游戏进程可以不同；首版允许手动配置，不把扫描整个游戏库作为前提。

首次配置展示关闭范围和强制结束行为；配置完成后正常使用保持一键执行。执行中展示阶段、取消按钮和结果；同一时间只允许一个清理会话运行。

不要求为了此功能让整个程序额外提权；若 LiteMonitor 原本以管理员运行，也不能扩大到系统服务或其他用户会话。

## 实现边界

拆分为配置与会话存储、进程识别与保护、应用退出、游戏启动与跟踪、应用恢复、界面入口。由协调器串行推进会话阶段，避免重复执行和 UI 阻塞。

复用既有主题与设置风格。保留现有内存清理功能，不把全局工作集修剪作为 Game Ready 默认步骤，避免将其与退出应用混为一谈。

首版不修改系统服务、启动项、注册表、电源计划或页面文件，不做常驻进程拦截，不承诺消除内存不足或提升固定比例的帧率。

## 验收

1. 保留名单内应用、系统关键组件、所选游戏在清理中始终存活；未选保留的普通前台与后台应用按规则退出。
2. 用可丢弃数据的测试应用验证正常退出、保存对话框阻塞、超时强制结束、权限不足、执行前自行退出及 PID 身份变化。
3. 验证启动失败、启动超时、目标游戏已运行、用户取消以及重复点击时的结果与恢复入口。
4. 关闭一次后新启动的普通应用继续运行，证明没有持续清理。
5. 恢复仅重启实际关闭且有启动入口的应用，支持失败重试、去重以及 LiteMonitor 重启后的恢复。
6. Steam 默认保留；启用退出策略时不误杀游戏，Steam 拒绝退出会明确报告。用《影之刃零》实机验证后才能记录兼容结论。
7. 需要 NVIDIA 截图的配置实测 Alt+F1 能生成截图；不能仅凭进程存在判定功能正常。
8. 展示实测可用物理内存变化；程序构建通过，并针对保护规则、会话状态与恢复规则执行针对性测试。
