# Game Ready 使用说明

## 开始使用

界面沿用 LiteMonitor 设置页的侧栏、设置分组和按钮。左侧切换“游戏准备”“保留名单”“清理与恢复”“后台应用恢复”；底部保留保存、恢复、预览和启动四个主要操作。程序路径放在“程序路径与高级配置”中，运行日志可按需展开。

运行二开版 `LiteMonitor.exe`，在主界面或托盘右键菜单选择 **Game Ready · 游戏准备**；设置页也提供入口。

1. 打开“游戏与启动”后会自动扫描 Steam / Epic 已安装游戏，选择列表中的游戏即可。游戏名称、平台入口和主程序路径会自动填写，也可点击“重新扫描游戏”。无需逐个导入。手动新增仅作为未识别游戏的补充入口。
2. 在“保留名单”中添加游戏期间仍需使用的应用。支持选择 EXE、从运行中应用添加，或每行手动输入一个完整路径。路径匹配不区分大小写；不是应用名称或路径前缀匹配。

   “从运行中应用添加”会显示应用图标、友好名称、程序文件名和窗口标题。同一 EXE 的多个进程合并为一行，窗口应用排在前面，其次是托盘匹配，普通后台进程默认隐藏，可通过“显示其他后台进程”或搜索找到。搜索不会清除勾选。托盘匹配使用系统可读的托盘记录或图标名称，不承诺反映实时托盘状态；无法读取图标时使用默认图标。图标仅在打开选择窗口时读取并在关闭后释放，不常驻扫描。
3. 默认保留 NVIDIA Overlay。若需要 Alt+F1，请保持开启，并在自己的 NVIDIA App 版本上确认截图功能仍然可用；预设本身不是兼容性保证。
4. 无主窗口的后台应用若需要自动恢复，可在“后台应用恢复”中填写其可直接启动的主程序路径。不要填写辅助进程或需要参数的宿主。
5. 点击“预览关闭范围”。这只读取快照，不会关闭任何应用。确认需要的应用已保护，然后在游戏页勾选已了解退出策略，保存配置。
6. 点击“清理并启动游戏”。应用先收到正常关闭请求，默认等待 10 秒，仍未退出的候选再被强制结束。保存对话框不会自动获得豁免，未保存内容可能丢失。
7. 游戏结束后，从菜单选择“恢复应用”。需要放弃旧恢复列表时，使用“放弃本次恢复”；原文件会改名为备份，不直接删除。

本机已通过只读扫描识别《影之刃零》（4115450），主程序为安装目录中的 platform\steam\PBZ.exe。扫描会排除解压、环境检测和崩溃上报等常见工具；识别结果会显示在游戏页，仍可人工修正特殊游戏的主程序。

扫描读取 Steam 注册表、多个库的 libraryfolders.vdf 与 appmanifest_*.acf，以及 Epic 的 .item 安装清单。只扫描清单所指向的游戏安装目录，不扫描整块磁盘；每个目录树限制深度、访问目录数与候选数量，跳过子目录链接和常见运行库目录。Epic 游戏通过 Epic 启动器入口启动。此版本未涵盖 Xbox / WeGame 或完全没有平台记录的独立游戏。

刷新会更新自动识别的程序路径，保留原有游戏名称、Steam 退出策略和延迟设置，不重复添加同一款平台游戏，也不删除手动添加的配置。无法读取的清单会被跳过并显示原因。

## 清理范围

只清理进入时快照中的普通应用，包括已经打开的窗口。系统关键进程、服务、驱动服务、桌面组件、其他登录会话、不同所有者、无法核实身份的进程，以及 LiteMonitor 自身和启动宿主不会被关闭。某些系统目录中的组件保守跳过，在预览中说明原因。

保留名单中的应用及能从本次进程快照确认的现有子进程受到保护。Windows 的父 PID 可能过期，程序会检查父子启动时间；没有父子关系的辅助进程需要单独加入保留名单。

清理完成后不再扫描或关闭新启动的普通应用。预览与实际执行之间进程可能变化，因此强制结束前会重新检查身份和保护规则，但不增加清理对象。执行中可以取消后续操作；已完成的退出不会自动撤销，可手动恢复。

## Steam 与游戏

默认在清理期间保留 Steam，游戏启动后正常关闭其主窗口，不强制结束客户端。

每款游戏可以单独开启“游戏启动后尝试退出 Steam”。目标进程出现后按配置延迟，再发出 Steam 的 `-shutdown` 正常退出请求，等待正常退出时间；Steam 仍在运行则报告并保留。若 Steam 组件被显式加入保留名单，保留名单优先，不退出客户端。

游戏进程出现或等待 30 秒不能证明已经不依赖 Steam。退出请求可能被 Steam 拒绝，也可能影响依赖客户端的游戏；必须逐款实测。程序不会通过杀整个 Steam 进程树来退出，以免将游戏一起结束。

《影之刃零》退出 Steam 后的兼容性尚未验证，默认不开启此选项。游戏退出后重新打开 Steam 只是为云存档同步提供条件，不能保证同步成功。

## 恢复边界

恢复只重新打开本次尝试退出后已不在运行的应用，不保证还原文档、标签页、原窗口或登录状态。有窗口的普通主程序自动记录为可恢复入口；识别为辅助进程或无明确启动入口的应用会标记需手动打开。已经运行的应用不会重复启动，失败项可以重试。

恢复列表会先落盘再执行退出；取消、启动失败、程序重启或意外中断后仍可读取。已有未处理列表时，不允许新会话静默覆盖。配置损坏时会报错，不会当作空白配置继续关闭应用。

## 文件与占用

- 配置：程序目录下 `game-ready.json`。
- 当前恢复列表：`game-ready-session.json`；放弃后的备份以 `.discarded-时间` 结尾。
- 请将便携版放在有写入权限的目录；配置和恢复列表无法保存时，不开始退出应用。
- 不新增 NuGet 依赖、常驻线程、全局清理定时器或 WMI 订阅。
- 游戏库仅在打开窗口或点击重新扫描时读取，扫描支持取消；进程完整快照仅在预览、清理和恢复阶段按需读取。游戏启动等待有超时，按候选游戏 EXE 名筛选进程。
- 游戏运行后，仅保留一个进程退出事件订阅，用于现有托盘通知；游戏退出或 LiteMonitor 退出时释放。关闭配置窗口不需要保持整套界面实例存活。
- 界面日志限制长度。清理不调用全局工作集修剪，不更改页面文件、系统服务、电源计划或启动项。

## 构建与验证

使用 .NET 8 SDK，普通构建：

```powershell
dotnet restore LiteMonitor.csproj --source https://api.nuget.org/v3/index.json
dotnet build LiteMonitor.csproj -c Release --no-restore
dotnet run --project test/GameReady/GameReady.Tests.csproj -c Release
dotnet run --project test/GameReady/GameReady.Tests.csproj -c Release -- --native
dotnet run --project test/GameReady.UI/GameReady.UI.csproj -c Release
```

核心测试使用模拟平台，不会清理用户应用。`--native` 只读枚举实际进程，并仅结束由测试自己创建的专用子进程。UI 测试只打开并渲染配置页，不启动游戏或清理应用。截图位于 `artifacts/game-ready-preview`。

便携发布（依赖 .NET 8 Windows Desktop Runtime，避免将整套运行时捆进发行包）：

```powershell
dotnet publish LiteMonitor.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o artifacts/GameReady-win-x64
```

必须保留整个发布目录中的资源和辅助库，不能只移动主 EXE。该版本沿用原项目的管理员运行清单与硬件监控初始化行为，Game Ready 不额外安装服务或驱动。

发布前仍需用户实机验收：选定游戏是否识别准确、保留软件的功能是否正常、该游戏退出 Steam 后是否受影响，以及真实应用保存提示和恢复行为。尚未对用户的真实应用执行批量关闭，也尚未验证游戏运行中的内存或帧率收益。
